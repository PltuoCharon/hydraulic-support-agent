# 05 防幻觉机制（三层结构）

## 概念
工业选型场景，LLM 编造一个参数就是事故。防幻觉不能靠一句
"请不要编造"的 prompt，要靠**流程结构**让模型接触不到"创作数字"的机会。

## 本项目三层结构
1. **参数确认不经过 LLM**：confirm 节点用 Python 模板复述工况参数，
   用户看到的数字与 LLM 抽取结果一字不差（W19-D4）；
2. **匹配数字来自引擎**：recommend 节点只调 run_match 存结果，
   不生成任何文字；支护强度等计算走 Support 类公式（代码），
   并标注"公式法估算(非实测)"与实测区分（W20-D2 source 字段）；
3. **解释只做复述**：explain 节点 prompt 注入完整结果 JSON，
   明令"相似度、型号、工况数值必须与 JSON 一字不差"，
   temperature=0 兜底（W19-D5）。

## 配套机制
- **越界拒答**：首轮无参数无数字的消息直接拒答（W20-D3 领域闸）；
- **数据缺失诚实标注**：web 查不到的参数标"未查到公开参数"，
  严禁编造（数据入库铁律）；
- **溯源强制化**：匹配候选/知识块/公式估算全部带 source 字段；
- **验证**：C01/C05 用例断言推荐数字与 W16 匹配结果一致（0.7957）。

## 踩坑
1. prompt 约束是必要不充分——GLM 仍会在 JSON 外包围栏、偶尔漏字段，
   解析层必须兜底（_parse_json）；
2. "改口"和"确认"的边界：含数字的消息一律视为参数修改，
   触发重新确认，不给幻觉留缝；
3. 防幻觉有代价：回复偏模板化，靠 prompt 里的话术示例缓解。
