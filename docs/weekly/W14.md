2. 支架接口：GET /api/supports/（架型前缀匹配含括号变体+阻力范围筛选+排除suspect）、GET /api/supports/{id}

4. POST /api/supports/filter：输入矿区id或手动工况，返回需求强度+合格支架清单
5. 统一响应格式 {code,data,msg} + 全局异常处理（404/500格式统一）
6. CORS 预配置（放行5173端口，为W21前端铺路）
7. pytest 五条断言落地（问题9闭环），commit 前先跑测试成为习惯
8. dict_enum 建表（问题10骨架），gas_level/support_type 标准枚举入库

## 坑与解决
1. support_models 真实列名与假设不符：work_force→working_resistance、type有独立列、
   intensity是varchar且含区间文本 → 前置 DESCRIBE 侦察 + 新建 parse_number 解析器统一驯服
   （Decimal/区间文本/None），读取层兼容，W15 再加数值列根治
2. type 列含8种括号变体（如 掩护式(急倾斜)）→ 精确匹配改为 LIKE 前缀匹配，基本架型枚举4种自动归并变体
3. ok() 包装时丢失字典大括号导致 SyntaxError → grep "return ok" 逐行检查；以后批量改动后先 python -c import 验证语法
4. .env 密码含特殊字符被 cut -f2 截断 → 统一用 python 提取：
   DBPW=$(python -c "from app.config import settings; print(settings.DB_PASSWORD)")
5. curl 未安装 / tests 目录不存在 / heredoc 粘贴串行 → 先 mkdir 再 cat，写完 tail 确认文件完整
