# 对话状态机设计（W19-D1）

## 1. 定位
选型是流程不是单轮问答。LangGraph 状态机保证"收集→确认→推荐→解释"的确定性流程，
节点内部由 LLM 处理自然语言理解与表达。thread_id=session_id，checkpointer 跨轮记忆。

## 2. 流程图
```mermaid
stateDiagram-v2
    [*] --> 参数收集
    参数收集 --> 参数收集: 参数不齐(追问缺失项)
    参数收集 --> 参数确认: 参数齐全(复述给用户确认)
    参数确认 --> 参数收集: 用户改口(更新参数重新确认)
    参数确认 --> 推荐: 用户确认
    推荐 --> 解释: run_matching返回Top-N,LLM组织解释
    解释 --> 改件重算: 用户问"缸径/压力改了会怎样"
    改件重算 --> 解释: recalc_params返回,继续解释
    解释 --> 参数收集: 用户开启新选型(重置)
3. State 定义（D2 实现）
表格
字段	类型	说明
params	dict	已收集参数 {coal_thickness, dip_angle, gas_level, roof...}
missing	list[str]	缺失字段列表
stage	str	当前阶段: collect/confirm/recommend/explain/recalc
messages	list	LangGraph 自带消息历史(add_messages)
match_result	dict	None	run_matching 返回(Top-N)
confirmed	bool	用户是否已确认参数
4. 必填参数与追问策略
必填: coal_thickness(煤层厚度)
重要可选: dip_angle(倾角)、gas_level(瓦斯)
追问话术由 LLM 生成，缺失列表由节点代码确定性计算（不靠模型自觉）
5. 条件边规则（D4 实现）
missing 非空 → 留在 collect（追问第一项缺失）
missing 空 且未确认 → confirm
confirm 阶段用户否定/改值 → 更新 params 回 collect/confirm
confirm 阶段用户肯定 → recommend
explain 阶段检出改件意图（缸径/压力数字） → recalc
6. 与 W18 Agent 的关系
W18 Agent（自由 function calling）保留在 /api/chat 通用问答
W19 状态机走新接口 /api/guide（引导式选型），system 内复用同一批工具
工具层 app/agent/tools.py 不变——状态机是它的上层编排
