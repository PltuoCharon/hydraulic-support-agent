# W35D1 Provenance 迁移策略

## 原则

存量 source 无法通过一次 SQL 安全拆成字段级 provenance。

采用：

规则提取
→ 候选断言
→ 人工审核
→ 正式写入

禁止：

source LIKE '%估算%'
→ 整行全部字段标记 estimated

## 原因

同一 support_models 记录可能同时存在：

- 原始参数
- 补录参数
- calculated 参数
- estimated 参数
- missing 参数

source 是整行混合文本，
不能确定关键词具体对应哪个字段。

## Phase 0

迁移前：

- mysqldump
- 保存测试基线
- 保存字段覆盖率
- 保留 source 原文

W35D1 不执行实际迁移。

## Phase 1

未来只创建空表：

- evidence_sources
- parameter_evidence

不修改 support_models 当前值。

不删除：

- source
- data_status

## Phase 2

优先实体化高置信来源：

- 厂家资料
- 标准
- 论文
- 学位论文
- 专利
- 政府技术文件
- 手册

## Phase 3

根据历史 source 生成候选断言。

允许使用关键词：

- 原始值
- 估算
- 复算
- 经验
- 未查到
- 矛盾
- 待核实

候选不能直接进入正式 provenance。

## Phase 4

人工审核：

- field_name
- 来源是否支持该字段
- 单位
- 单值或范围
- value_origin
- verification_status
- 是否 derived
- 是否存在冲突
- 是否 selected

## Phase 5

审核后写入 parameter_evidence。

support_models 继续作为业务主表。

## API 兼容期

未来 API 可增加：

- evidence
- value_origin
- verification_status
- formula_id

旧 source / data_status 暂时继续保留。

在 provenance 覆盖稳定前不得删除旧 source。

## source 启发式退出

当前前端和 queries 仍通过：

- 估算
- 复算
- 未查到

等 source 关键词生成 badge / est_fields。

provenance 覆盖稳定后，
逐步替换为结构化状态字段。

## 优先迁移字段

第一批：

- manufacturer
- intensity
- weight
- initial_force

第二批：

- center_dist
- canopy_len

第三批：

- type
- working_resistance
- height_min
- height_max

## calculated 与 estimated

确定性公式 + 已核实输入：
calculated

确定性公式 + 任一经验输入：
estimated

## legacy 公式

Formula Registry 中 status=legacy_review 的公式
允许作为历史 provenance 的 formula_id。

但不得因为存在 formula_id
就自动把 verification_status 标记为 verified。

## 回滚

provenance 初期只是附加层。

不修改 support_models 主值，
因此出现问题时可停止读取 provenance，
不会破坏现有业务链。

这是增量迁移方案。
