# W35D3 推荐支架到立柱设计参数传递契约

## 1. 当前问题

W34 结果页中的“进入立柱设计”当前仅跳转：

`/calc?m=column`

未传递当前支架的型号、工作阻力或来源信息。

ColumnView 当前存在独立计算示例默认值，因此用户可能误以为立柱计算正在使用刚才选择的推荐支架参数。

W35D3 目标是建立显式、可追溯的设计上下文传递。

## 2. 来源类型

允许的来源类型：

- `selected_support`
- `calculated_requirement`
- `user_input`

不得把不同来源的数值静默合并。

## 3. selected_support 传递字段

从推荐结果进入立柱设计时允许自动传递：

- `support_model`
- `working_resistance`
- `source`
- `data_status`（如果当前结果实际提供）

其中 `working_resistance` 在立柱设计侧映射为：

`target_resistance_kn`

来源类型：

`selected_support`

含义：

“按当前所选支架的额定工作阻力进行立柱参数设计辅助”。

## 4. 不自动传递的字段

以下字段不得由推荐支架入口静默生成：

- `n`
- `p_mpa`
- `eta`
- `p_set_kn`
- `Ks`
- `safety_factor`

上述参数必须由用户显式输入，或未来由已核 evidence / formula rule 提供。

未知保持 NULL。

## 5. eta 与 Ks

W35D2 已确认：

`eta != Ks`

`Ks` 是液压支架支撑效率。

Column 公式中的 `eta` 属于历史立柱计算参数，其定义和来源将在 W35D5 继续审计。

W35D3 不修改该公式，只要求 eta 来源显式，不允许从 Ks 自动映射。

## 6. calculated_requirement

未来从需求工作阻力链进入立柱设计时：

`target_resistance_kn = required_working_resistance_kn`

来源类型：

`calculated_requirement`

应同时保存：

- Formula IDs
- 输入来源
- 计算结果来源

不得与 `selected_support.working_resistance` 静默覆盖或混为同一个来源。

## 7. Transfer Payload

第一版传递对象包含：

- `version`
- `source_type`
- `target.support_model`
- `target.resistance_kn`
- `provenance.source_text`
- `provenance.data_status`
- `confirmed`

设计输入参数 `n / p_mpa / eta / p_set_kn` 不属于该对象的自动填充值。

## 8. UI 规则

ColumnView 应显示“设计上下文”。

至少显示：

- 来源类型
- 支架型号
- 目标工作阻力
- 数据来源
- 数据状态

自动带入的设计工作阻力必须有明确的来源标签。

其他待输入参数显示为“待设计输入”。

不得让示例默认值看起来像已从推荐支架获取。

## 9. 示例参数

当前 ColumnView 的：

- 2533 kN
- 1 根
- 31.5 MPa
- eta=1.0
- 1900 kN

只允许作为：

`计算示例`

不得继续作为受控设计流程的隐式初始参数。

## 10. W35D3 实现边界

本阶段实现：

推荐结果
→ Transfer Payload
→ ColumnView 设计上下文
→ 用户确认
→ 立柱计算

本阶段不处理：

- eta 物理定义重构；
- Ks 到 eta 的映射；
- 自动推断立柱数量；
- 自动推断泵站压力；
- 自动补齐初撑力；
- 立柱完整制造级设计。

上述计算链补强进入 W35D5。
